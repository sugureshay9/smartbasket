# SmartBasket - Deployment Guide\n\n## Prerequisites\n\n- Node.js 18+\n- MongoDB Atlas account\n- Redis (cloud or local)\n- Cloudinary account\n- Firebase account\n- GitHub account\n- Railway/Render account (for backend)\n- Vercel account (for frontend)\n- Google Play Developer account (for mobile)\n\n---\n\n## Backend Deployment (Railway/Render)\n\n### Step 1: Prepare Environment Variables\n\nCreate `.env.production` file with your production credentials:\n\n```env\n# Database\nMONGODB_URI=mongodb+srv://user:password@cluster.mongodb.net/smartbasket\nREDIS_URL=redis://your-redis-url:6379\n\n# External Price Server\nEXTERNAL_PRICE_API=https://your-price-server.com/api\nEXTERNAL_PRICE_API_KEY=your_production_api_key\n\n# JWT\nJWT_SECRET=your_very_secure_jwt_secret_min_32_chars\nJWT_EXPIRE=7d\nJWT_REFRESH_SECRET=your_very_secure_refresh_secret\nJWT_REFRESH_EXPIRE=30d\n\n# File Upload\nCLOUDINARY_CLOUD_NAME=your_cloud_name\nCLOUDINARY_API_KEY=your_api_key\nCLOUDINARY_API_SECRET=your_api_secret\n\n# Environment\nNODE_ENV=production\nPORT=5000\nCLIENT_URL=https://your-frontend-domain.com\n```\n\n### Step 2: Deploy to Railway\n\n#### Via GitHub:\n\n1. Push code to GitHub\n2. Go to [railway.app](https://railway.app)\n3. Click \"New Project\"\n4. Select \"Deploy from GitHub repo\"\n5. Connect your GitHub account\n6. Select `smartbasket` repository\n7. Select `server` directory as root\n\n#### Via Railway CLI:\n\n```bash\nnpm install -g @railway/cli\nrailway login\ncd server\nrailway up\n```\n\n### Step 3: Configure Environment on Railway\n\n1. Go to Project Settings\n2. Add variables from `.env.production`\n3. Deploy the changes\n\n---\n\n## Frontend Deployment (Vercel)\n\n### Step 1: Prepare Frontend\n\nCreate `.env.production.local` in `client/` directory:\n\n```env\nNEXT_PUBLIC_API_URL=https://your-backend-railway-url/api\n```\n\n### Step 2: Deploy to Vercel\n\n#### Via Vercel CLI:\n\n```bash\nnpm install -g vercel\ncd client\nvercel --prod\n```\n\n#### Via GitHub:\n\n1. Connect Vercel to GitHub\n2. Select `smartbasket` repository\n3. Set root directory to `client`\n4. Add environment variables\n5. Deploy\n\n### Step 3: Configure Domain\n\n1. Go to Vercel Project Settings\n2. Add your custom domain\n3. Update DNS records\n\n---\n\n## Mobile App Deployment (Play Store)\n\n### Step 1: Setup EAS Account\n\n```bash\nnpm install -g eas-cli\ncd mobile\neas login\n```\n\n### Step 2: Configure app.json\n\nUpdate `mobile/app.json`:\n\n```json\n{\n  \"expo\": {\n    \"name\": \"SmartBasket\",\n    \"slug\": \"smartbasket\",\n    \"owner\": \"your-username\",\n    \"version\": \"1.0.0\",\n    \"runtimeVersion\": \"1.0.0\",\n    \"ios\": {\n      \"bundleIdentifier\": \"com.smartbasket.app\"\n    },\n    \"android\": {\n      \"package\": \"com.smartbasket.app\"\n    }\n  }\n}\n```\n\n### Step 3: Create Release Build\n\n```bash\neas build --platform android --release\n```\n\nThis will generate an APK/AAB file.\n\n### Step 4: Setup Google Play Console\n\n1. Go to [Google Play Console](https://play.google.com/console)\n2. Create new app \"SmartBasket\"\n3. Fill app details\n4. Add screenshots (minimum 2)\n5. Add app description\n6. Set privacy policy URL\n7. Set content rating\n\n### Step 5: Upload Build\n\n```bash\neas submit --platform android --latest\n```\n\nOR manually upload to Google Play Console:\n\n1. Go to \"Release\" → \"Production\"\n2. Upload the APK/AAB file\n3. Fill release notes\n4. Submit for review\n\n---\n\n## Database Setup\n\n### MongoDB Atlas\n\n1. Go to [MongoDB Atlas](https://www.mongodb.com/cloud/atlas)\n2. Create a new cluster\n3. Configure network access (whitelist your IPs)\n4. Create database user\n5. Get connection string\n6. Use in `MONGODB_URI`\n\n### Redis\n\n#### Option 1: Redis Cloud\n\n1. Go to [Redis Cloud](https://redis.com/try-free/)\n2. Create free database\n3. Get connection URL\n4. Use in `REDIS_URL`\n\n#### Option 2: Self-hosted\n\n```bash\ndocker run -d -p 6379:6379 redis:7-alpine\n```\n\n---\n\n## Docker Deployment\n\n### Build Docker Images\n\n```bash\n# Backend\ncd server\ndocker build -t smartbasket-backend .\n\n# Run\ndocker run -p 5000:5000 --env-file .env.production smartbasket-backend\n```\n\n### Docker Compose (Production)\n\n```bash\ndocker-compose -f docker-compose.yml up -d\n```\n\n---\n\n## CI/CD Pipeline (GitHub Actions)\n\n### Backend CI/CD\n\nCreate `.github/workflows/backend-ci.yml`:\n\n```yaml\nname: Backend CI/CD\n\non:\n  push:\n    branches: [main]\n    paths:\n      - 'server/**'\n  pull_request:\n    branches: [main]\n\njobs:\n  build-and-deploy:\n    runs-on: ubuntu-latest\n    steps:\n      - uses: actions/checkout@v3\n      \n      - name: Setup Node\n        uses: actions/setup-node@v3\n        with:\n          node-version: '18'\n      \n      - name: Install dependencies\n        working-directory: ./server\n        run: npm install\n      \n      - name: Run tests\n        working-directory: ./server\n        run: npm test\n      \n      - name: Build\n        working-directory: ./server\n        run: npm run build\n      \n      - name: Deploy to Railway\n        if: github.event_name == 'push' && github.ref == 'refs/heads/main'\n        run: |\n          npm install -g @railway/cli\n          railway up\n        env:\n          RAILWAY_TOKEN: ${{ secrets.RAILWAY_TOKEN }}\n```\n\n### Frontend CI/CD\n\nCreate `.github/workflows/frontend-ci.yml`:\n\n```yaml\nname: Frontend CI/CD\n\non:\n  push:\n    branches: [main]\n    paths:\n      - 'client/**'\n  pull_request:\n    branches: [main]\n\njobs:\n  build-and-deploy:\n    runs-on: ubuntu-latest\n    steps:\n      - uses: actions/checkout@v3\n      \n      - name: Setup Node\n        uses: actions/setup-node@v3\n        with:\n          node-version: '18'\n      \n      - name: Install dependencies\n        working-directory: ./client\n        run: npm install\n      \n      - name: Lint\n        working-directory: ./client\n        run: npm run lint\n      \n      - name: Build\n        working-directory: ./client\n        run: npm run build\n      \n      - name: Deploy to Vercel\n        if: github.event_name == 'push' && github.ref == 'refs/heads/main'\n        uses: vercel/action@v4\n        with:\n          vercel-token: ${{ secrets.VERCEL_TOKEN }}\n          vercel-org-id: ${{ secrets.VERCEL_ORG_ID }}\n          vercel-project-id: ${{ secrets.VERCEL_PROJECT_ID }}\n          working-directory: ./client\n```\n\n---\n\n## Health Checks\n\n### Backend Health\n\n```bash\ncurl https://your-backend-url/health\n```\n\nExpected response:\n```json\n{\n  \"status\": \"ok\",\n  \"timestamp\": \"2024-01-01T00:00:00Z\",\n  \"environment\": \"production\"\n}\n```\n\n---\n\n## Monitoring & Logging\n\n### Sentry (Error Tracking)\n\n1. Create Sentry account\n2. Create project\n3. Add to backend `.env`:\n```env\nSENTRY_DSN=your_sentry_dsn\n```\n\n### Datadog (Performance Monitoring)\n\n1. Create Datadog account\n2. Get API key\n3. Add to backend `.env`:\n```env\nDATADOG_API_KEY=your_api_key\nDATADOG_SITE=datadoghq.com\n```\n\n---\n\n## Troubleshooting\n\n### Railway Deployment Issues\n\n```bash\n# Check logs\nrailway logs\n\n# Check status\nrailway status\n\n# Redeploy\nrailway up\n```\n\n### Vercel Deployment Issues\n\n```bash\n# Check deployment\nvercel ls\n\n# View logs\nvercel logs\n\n# Redeploy\nvercel --prod\n```\n\n### MongoDB Connection Issues\n\n1. Verify connection string\n2. Check whitelist IP addresses\n3. Verify credentials\n4. Check network connectivity\n\n---\n\n## Rollback Strategy\n\n### Railway\n```bash\nrailway rollback\n```\n\n### Vercel\n1. Go to Deployments\n2. Click on previous deployment\n3. Click \"Promote to Production\"\n\n---\n\n## Security Checklist\n\n- ✅ Change all default credentials\n- ✅ Use strong JWT secrets (min 32 chars)\n- ✅ Enable HTTPS everywhere\n- ✅ Setup rate limiting\n- ✅ Configure CORS properly\n- ✅ Enable database backups\n- ✅ Setup monitoring and alerts\n- ✅ Use environment variables for secrets\n- ✅ Keep dependencies updated\n- ✅ Enable security headers\n\n---\n\n## Performance Optimization\n\n### Backend\n- Use Redis caching\n- Enable compression\n- Setup CDN for static assets\n- Optimize database queries\n- Use connection pooling\n\n### Frontend\n- Enable code splitting\n- Optimize images\n- Use lazy loading\n- Minify CSS/JS\n- Setup caching headers\n\n---\n\n## Cost Optimization\n\n- Use free tier services where possible\n- Monitor API usage\n- Setup billing alerts\n- Optimize database queries\n- Use auto-scaling\n
